# FrameFlow 服务器部署与域名切换指南

> 适用项目：当前仓库中的 FrameFlow 视频制作与发布平台
>
> 推荐环境：Ubuntu 22.04/24.04、单台 Linux 服务器、Docker Engine + Docker Compose、宿主机 Nginx、HTTPS 域名
>
> 示例域名：`video.example.com`。执行时必须替换成真实域名。
> 更新日期：2026-09-16

---

## 1. 最终部署结构

推荐使用同域名部署，浏览器、API、媒体和公开审核视频共用一个 HTTPS 域名：

```text
Internet
   │
   │  https://video.example.com
   ▼
宿主机 Nginx（80/443、HTTPS 证书）
   │
   │  http://127.0.0.1:5173
   ▼
frontend 容器中的 Nginx
   ├── /                    → Vue 前端与 SPA 路由
   ├── /api/                → api:8000
   ├── /storage/            → api:8000
   └── /videos-pub/         → api:8000
                              │
                              ├── PostgreSQL：db:5432
                              ├── Redis：redis:6379
                              ├── Celery Worker
                              └── ./storage 持久化媒体目录
```

公网只开放：

- `22/tcp`：SSH，建议仅允许管理 IP。
- `80/tcp`：HTTP 跳转 HTTPS、Let's Encrypt HTTP-01 验证。
- `443/tcp`：正式 HTTPS 服务。

不要向公网开放：

- PostgreSQL `5432`
- Redis `6379`
- FastAPI `8000`
- 前端容器映射端口 `5173`

生产 Compose 会让 `5173` 只监听宿主机 `127.0.0.1`，供宿主机 Nginx 使用。

---

## 2. 部署前准备

需要准备：

1. 一台具有固定公网 IPv4 的 Linux 服务器。
2. 一个可以修改 DNS 的域名，例如 `video.example.com`。
3. 服务器 SSH 管理权限和 `sudo` 权限。
4. 项目代码的 Git 仓库地址，或完整项目压缩包。
5. 足够的磁盘空间；视频文件保存在项目根目录的 `storage/`。
6. 生产环境使用的管理员密码、数据库密码、JWT 密钥和 Secret 加密密钥。

建议最低配置：

```text
CPU：2 核
内存：4 GB
磁盘：50 GB 起，根据视频数量扩容
系统：Ubuntu 22.04/24.04 LTS 64 位
```

如果本机生成、转码的视频较大，建议为 `storage/` 使用独立数据盘，并配置磁盘空间监控。

## 3. 配置域名 DNS

在 DNS 管理后台添加：

```text
记录类型：A
主机记录：video
记录值：服务器公网 IPv4
TTL：300 或默认值
```

对应结果：

```text
video.example.com → 服务器公网 IPv4
```

只有服务器已经正确配置 IPv6 时才添加 `AAAA` 记录。错误的 `AAAA` 记录会导致部分客户端优先走 IPv6 后访问失败。

检查解析：

```bash
dig +short video.example.com A
```

也可以使用：

```bash
nslookup video.example.com
```

输出应当是服务器公网 IP。申请 HTTPS 证书前必须先确认 DNS 已生效。

仓库现有 `tbpud.conf` 中出现了 `tbpub.terabox.co.jp` 和 `pub.u88.pub` 两个候选域名。如果这两个域名都要使用：

- 先选一个作为正式的 canonical 域名，并把它写入 `PUBLIC_BASE_URL`。
- 两个域名都要配置 DNS、Nginx `server_name` 和 HTTPS 证书。
- `CORS_ORIGINS` 填写两个完整 HTTPS Origin，以逗号分隔。
- 第三方平台审核和 Instagram `video_url` 始终使用 canonical 域名，避免同一视频出现多套公网地址。

## 4. 安装服务器基础组件

### 4.1 安装常用工具和 Nginx

```bash
sudo apt update
sudo apt install -y ca-certificates curl git nginx snapd
sudo systemctl enable --now nginx
```

### 4.2 安装 Docker Engine 与 Compose Plugin

生产服务器建议通过 Docker 官方 APT 仓库安装，不建议使用面向开发/测试的便捷安装脚本。完整且持续更新的命令请以 [Docker 官方 Ubuntu 安装文档](https://docs.docker.com/engine/install/ubuntu/) 为准。

安装完成后检查：

```bash
sudo docker version
sudo docker compose version
sudo systemctl enable --now docker
```

如果将当前用户加入 `docker` 组，该用户将获得近似 root 的 Docker 控制权限。没有明确需要时，生产服务器可以继续使用 `sudo docker ...`。

### 4.3 防火墙与云安全组

在云厂商安全组中只开放 `22`、`80`、`443`。Docker 官方说明指出，发布到所有网卡的容器端口可能绕过部分 UFW/firewalld 规则，因此本指南同时通过 Compose 取消数据库/API端口发布，并把前端映射限制到 `127.0.0.1`；不要只依赖 UFW。

## 6. 创建生产环境变量

在项目根目录创建 `.env`：

```bash
cd /opt/frameflow
cp .env.example .env
chmod 600 .env
nano .env
```

生产配置示例：

```env
APP_ENV=production
APP_HOST=0.0.0.0
APP_PORT=8000
PUBLIC_BASE_URL=https://video.example.com

POSTGRES_DB=video_platform
POSTGRES_USER=video_app
POSTGRES_PASSWORD=<使用独立的强随机密码>
DATABASE_URL=postgresql+psycopg://video_app:<与上面相同的数据库密码>@db:5432/video_platform

REDIS_URL=redis://redis:6379/0
CELERY_BROKER_URL=redis://redis:6379/0
CELERY_RESULT_BACKEND=redis://redis:6379/1
CELERY_TASK_ALWAYS_EAGER=false
CELERY_MAX_RETRIES=3

JWT_SECRET_KEY=<至少32字节的随机字符串>
JWT_EXPIRE_MINUTES=120
SECRET_ENCRYPTION_KEY=<另一条独立的至少32字节随机字符串>

STORAGE_TYPE=local
STORAGE_PATH=/app/storage
UPLOAD_MAX_SIZE_MB=10
FFMPEG_BINARY=ffmpeg
FFPROBE_BINARY=ffprobe
GENERATION_POLL_INTERVAL=2
GENERATION_TIMEOUT=120

MINIMAX_API_BASE_URL=https://api.minimax.io
MINIMAX_POLL_INTERVAL_SECONDS=10
MINIMAX_GENERATION_TIMEOUT_SECONDS=900
MINIMAX_HTTP_TIMEOUT_SECONDS=60

CORS_ORIGINS=https://video.example.com
AUTO_SEED=true
DEFAULT_ADMIN_USERNAME=admin
DEFAULT_ADMIN_PASSWORD=<生产管理员强密码>
DEFAULT_USER_USERNAME=
DEFAULT_USER_PASSWORD=
```

生成随机值的示例：

```bash
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 24
```

分别用于：

1. `JWT_SECRET_KEY`
2. `SECRET_ENCRYPTION_KEY`
3. `POSTGRES_PASSWORD`

注意：

- 三个值不要复用。
- `.env` 不得提交到 Git，也不要发送到聊天、工单或截图中。
- 数据库密码如果含 `@`、`:`、`/`、`#` 等 URL 特殊字符，写入 `DATABASE_URL` 前必须进行 URL 编码。使用十六进制随机值可避免该问题。
- 如果是从旧服务器迁移数据库，必须继续使用旧服务器的 `SECRET_ENCRYPTION_KEY`，否则数据库中已有的模型 API Key、平台 Access Token 将无法解密。
- `APP_ENV=production` 会拒绝项目示例密码 `Admin123!`、`User123!` 等，必须更换。
- 如果同时使用 `video.example.com` 和 `www.video.example.com`，两个来源都要加入 `CORS_ORIGINS`，以逗号分隔。

## 7. 创建生产 Compose 文件

开发用 `docker-compose.yml` 将数据库、Redis、API 暴露到宿主机，生产环境不应直接照搬。Docker 官方建议为生产环境准备独立 Compose 配置；参见 [Use Compose in production](https://docs.docker.com/compose/how-tos/production/)。

在项目根目录新建 `docker-compose.production.yml`：

```yaml
services:
  db:
    image: postgres:17-alpine
    restart: unless-stopped
    environment:
      POSTGRES_DB: ${POSTGRES_DB}
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    expose:
      - "5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 5s
      timeout: 5s
      retries: 20

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    command: redis-server --appendonly yes
    volumes:
      - redis_data:/data
    expose:
      - "6379"
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 20

  api:
    build: ./backend
    restart: unless-stopped
    env_file: .env
    command: sh -c "alembic upgrade head && python -m app.db.init_db && uvicorn app.main:app --host 0.0.0.0 --port 8000"
    volumes:
      - ./storage:/app/storage
    expose:
      - "8000"
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health')"]
      interval: 5s
      timeout: 5s
      retries: 20

  worker:
    build: ./backend
    restart: unless-stopped
    env_file: .env
    command: celery -A app.tasks.celery_app.celery_app worker --loglevel=INFO --concurrency=2
    volumes:
      - ./storage:/app/storage
    depends_on:
      api:
        condition: service_healthy
      redis:
        condition: service_healthy

  frontend:
    build: ./frontend
    restart: unless-stopped
    ports:
      - "127.0.0.1:5173:80"
    depends_on:
      api:
        condition: service_healthy

volumes:
  postgres_data:
  redis_data:
```

要点：

- `db`、`redis`、`api` 只有 Compose 内部网络可以访问。
- `frontend` 只监听服务器回环地址 `127.0.0.1:5173`。
- API 和 Worker 共同挂载项目根目录下的 `./storage`。
- `restart: unless-stopped` 使服务在服务器重启后恢复。
- 不要执行 `docker compose down -v`，`-v` 会删除 PostgreSQL/Redis 数据卷。

检查最终配置：

```bash
cd /opt/frameflow
sudo docker compose -p frameflow -f docker-compose.production.yml config --quiet
```

不要把不带 `--quiet` 的完整配置输出粘贴到公开位置，因为渲染结果可能含有环境变量。

## 9. 配置宿主机 Nginx 反向代理

创建配置：

```bash
sudo nano /etc/nginx/sites-available/frameflow.conf
```

写入以下内容，并替换域名：

```nginx
upstream frameflow_frontend {
    server 127.0.0.1:5173;
    keepalive 16;
}

server {
    listen 80;
    listen [::]:80;
    server_name video.example.com;

    client_max_body_size 12m;

    location /videos-pub/ {
        proxy_pass http://frameflow_frontend;
        proxy_http_version 1.1;
        proxy_buffering off;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://frameflow_frontend;
        proxy_http_version 1.1;
        proxy_request_buffering off;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }
}
```

这里让所有请求先进入 frontend 容器：

- Vue 的 `/publish/{postId}` 由前端 SPA 处理。
- `/api/`、`/storage/`、`/videos-pub/` 由 frontend 容器继续代理到 FastAPI。
- 刷新 `/publish/mock-post-...` 不会返回 404。

启用配置：

```bash
sudo ln -sfn /etc/nginx/sites-available/frameflow.conf /etc/nginx/sites-enabled/frameflow.conf
sudo nginx -t
sudo systemctl reload nginx
```

如果服务器默认站点占用了相同域名或成为冲突的默认 server，应先检查：

```bash
sudo nginx -T
```

确认冲突配置后再停用，不要在未确认路径时批量删除 Nginx 配置。

项目根目录现有 `tbpud.conf` 使用了内网地址 `192.168.10.143:8000` 并单独从 `/home/user/tbpub/html` 提供静态文件。如果采用本指南的同机 Docker 部署，应改用上面的配置，把整个站点代理到 `127.0.0.1:5173`；不要继续把公网请求直接转发到 FastAPI `8000`。

Nginx 的 `proxy_set_header`、`proxy_pass` 等行为可参考 [Nginx 官方反向代理模块文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)。

### 上传大小注意事项

当前项目有两层 Nginx：

1. 宿主机 Nginx：本节的 `client_max_body_size`。
2. frontend 容器 Nginx：`frontend/nginx.conf` 中的 `client_max_body_size`。

两层限制都必须大于后端 `UPLOAD_MAX_SIZE_MB` 加上 multipart 开销。只提高宿主机的限制，内部 Nginx 仍可能返回 `413 Request Entity Too Large`。当前后端默认 10 MB，因此两层建议至少 12 MB；如果以后把后端提高到 50 MB，两层 Nginx 也要同步提高，例如 55–60 MB，然后重建 frontend 镜像。

## 10. 配置 HTTPS

HTTP-01 验证要求公网可以访问服务器的 `80/tcp`；Let's Encrypt 对该验证方式的说明见 [Challenge Types](https://letsencrypt.org/docs/challenge-types/)。

安装 Certbot：

```bash
sudo snap install --classic certbot
sudo ln -sfn /snap/bin/certbot /usr/local/bin/certbot
```

申请并自动配置 Nginx：

```bash
sudo certbot --nginx -d video.example.com
```

按提示选择把 HTTP 重定向到 HTTPS。完成后检查：

```bash
sudo nginx -t
sudo systemctl reload nginx
curl -I https://video.example.com/
```

测试自动续期：

```bash
sudo certbot renew --dry-run
```

Certbot 的当前安装和续期说明见 [Certbot 官方 Nginx 指南](https://certbot.eff.org/instructions?os=snap&ws=nginx)。

## 11. 从本地 IP/localhost 切换到域名

### 11.1 必须修改的值

| 本地/开发值 | 生产值 |
|---|---|
| `PUBLIC_BASE_URL=http://localhost:8000` | `PUBLIC_BASE_URL=https://video.example.com` |
| `CORS_ORIGINS=http://localhost:5173,...` | `CORS_ORIGINS=https://video.example.com` |
| 浏览器访问 `http://localhost:5173` | `https://video.example.com` |
| 审核视频 `http://localhost:5173/videos-pub/{id}` | `https://video.example.com/videos-pub/{id}` |
| Instagram `video_url=http://...` | `video_url=https://video.example.com/videos-pub/{id}` |

修改 `.env` 后重启 API 和 Worker：

```bash
sudo docker compose -p frameflow -f docker-compose.production.yml up -d --build api worker frontend
```

### 11.2 不要修改的值

以下地址属于 Docker 内部服务发现或容器内部健康检查，不应替换为公网域名：

```text
db:5432
redis:6379
api:8000
http://127.0.0.1:8000/health（API 容器内部）
```

前端生产环境继续使用：

```env
VITE_API_BASE_URL=/api/v1
```

不要把它改成：

```env
VITE_API_BASE_URL=http://服务器IP:8000/api/v1
```

根相对路径会自动继承当前页面的协议和域名，可以避免更换服务器或域名后重新写数据库：

```text
/publish/mock-post-...
/api/v1/...
/storage/videos/...
/videos-pub/{video_id}
```

例如页面保存的是：

```text
/publish/mock-post-abc123
```

在本地自动解析为：

```text
http://localhost:5173/publish/mock-post-abc123
```

部署后自动解析为：

```text
https://video.example.com/publish/mock-post-abc123
```

视频数据库记录同样使用 `/storage/...` 根相对 URL，因此无需批量把 `localhost` 替换为域名。

### 11.3 第三方平台的 video_url 是例外

Instagram/Meta 服务器无法理解项目内部的相对地址，也无法访问 `localhost`、`127.0.0.1`、`192.168.x.x` 或公司 VPN 地址。

传给 Instagram Adapter 的 `platform_payload.video_url` 必须是完整公网 HTTPS URL：

```text
https://video.example.com/videos-pub/{video_id}
```

不能传：

```text
/videos-pub/{video_id}
http://localhost:5173/videos-pub/{video_id}
http://192.168.10.143/videos-pub/{video_id}
/storage/videos/xxx.mp4
```

建议给第三方平台统一使用稳定的公开审核接口 `/videos-pub/{video_id}`，不要使用内部文件 key。该接口无需登录，因此任何获得链接的人都可以读取视频；视频软删除后返回 404。

目前 `PUBLIC_BASE_URL` 不会自动替 Instagram 拼接 `video_url`。发布时仍需在 Instagram 平台覆盖字段中填写完整的 `https://域名/videos-pub/{video_id}`。

## 12. 上线验收清单

### 12.1 容器和服务

```bash
sudo docker compose -p frameflow -f docker-compose.production.yml ps
sudo docker compose -p frameflow -f docker-compose.production.yml logs --tail=100 api worker
```

确认：

- `db`、`redis`、`api` 为 healthy。
- `worker`、`frontend` 为 running。
- API 日志没有 Migration、数据库连接或示例密码错误。
- Worker 日志中已加载生成和发布任务。

### 12.2 HTTPS 与 SPA 路由

```bash
curl -I https://video.example.com/
curl -I https://video.example.com/login
```

在浏览器中验证：

1. 登录后台。
2. 打开视频列表和视频详情。
3. 创建一条 Mock 发布。
4. 从发布记录打开 `/publish/mock-post-...`。
5. 直接刷新结果页面，确认不会进入 404。

### 12.3 公开审核视频

将真实 UUID 替换进去：

```bash
curl -I "https://video.example.com/videos-pub/<video_id>"
curl -L --range 0-1023 -o /tmp/frameflow-range-test.bin \
  "https://video.example.com/videos-pub/<video_id>"
```

确认：

- 不携带登录 Token 也能访问。
- HTTP 状态为 200 或 Range 请求对应的 206。
- `Content-Type` 为正确的视频类型。
- URL 不会跳回 localhost、内网 IP 或 HTTP。
- 海外网络可以访问；Meta 抓取不应依赖公司 VPN、Cookie 或登录态。

### 12.4 安全检查

从另一台机器确认以下端口不能直接访问：

```text
服务器公网IP:5432
服务器公网IP:6379
服务器公网IP:8000
服务器公网IP:5173
```

并确认：

- 默认密码已经更换。
- `.env` 权限为 `600`。
- `.env` 没有进入 Git。
- 生产平台的 Access Token/API Key 只通过管理后台配置。
- PostgreSQL、Redis 没有公网安全组规则。

## 13. 数据备份

必须同时备份：

1. PostgreSQL 数据库。
2. 项目根目录 `storage/`。
3. `.env` 中的 `SECRET_ENCRYPTION_KEY`，应单独保存在安全的密码库/Secrets Manager。

### 13.1 PostgreSQL 逻辑备份

```bash
cd /opt/frameflow
mkdir -p backups
sudo docker compose -p frameflow -f docker-compose.production.yml exec -T db \
  pg_dump -U video_app -d video_platform -Fc \
  > "backups/postgres-$(date +%Y%m%d-%H%M%S).dump"
```

### 13.2 Storage 备份

```bash
cd /opt/frameflow
tar -czf "backups/storage-$(date +%Y%m%d-%H%M%S).tar.gz" storage
```

备份文件应复制到另一台服务器或对象存储，不能只留在同一块系统盘。Docker 关于 Volume 备份与恢复的说明见 [Docker Volumes](https://docs.docker.com/engine/storage/volumes/)。

定期做恢复演练；只有能成功恢复的备份才算有效备份。

## 14. 日常更新部署

更新前先备份数据库和 `storage/`，然后：

```bash
cd /opt/frameflow
git status
git pull --ff-only
sudo docker compose -p frameflow -f docker-compose.production.yml build
sudo docker compose -p frameflow -f docker-compose.production.yml up -d
sudo docker compose -p frameflow -f docker-compose.production.yml ps
sudo docker compose -p frameflow -f docker-compose.production.yml logs --tail=200 api worker frontend
```

API 启动时会执行 Alembic Migration。不要同时启动多个正在执行 Migration 的 API 实例。

更新后至少检查：

```text
登录
视频播放
公开 videos-pub URL
生成一条 Mock 视频
发布一条 Mock 记录
/publish/{postId} 刷新
Celery Worker 日志
```

## 15. 常见故障

### 15.1 域名仍指向旧 IP

检查：

```bash
dig +short video.example.com A
```

确认 DNS 记录、TTL、本机 DNS 缓存和是否存在错误的 `AAAA`。

### 15.2 HTTPS 证书申请失败

检查：

- DNS 是否已经指向当前服务器。
- 云安全组和服务器防火墙是否开放 80/443。
- Nginx 是否正常监听 80。
- 域名是否被其他 server block 抢先处理。
- CDN/代理是否影响验证；首次排障可临时切到 DNS only。

### 15.3 访问 `/publish/mock-post-...` 返回 404

检查：

- 宿主机 Nginx 是否把整个 `/` 代理到 `127.0.0.1:5173`。
- 是否误把 `/publish/` 当成本地静态目录。
- frontend 容器是否使用当前代码重新构建。
- 浏览器是否缓存了旧前端资源。

重新构建：

```bash
sudo docker compose -p frameflow -f docker-compose.production.yml up -d --build frontend api
```

### 15.4 API 请求 502

```bash
sudo docker compose -p frameflow -f docker-compose.production.yml ps
sudo docker compose -p frameflow -f docker-compose.production.yml logs --tail=200 api db redis
curl -I http://127.0.0.1:5173/
```

通常是 API 启动失败、数据库未 healthy、环境变量错误或 Migration 失败。

### 15.5 上传返回 413

同时检查：

```text
宿主机 Nginx client_max_body_size
frontend/nginx.conf client_max_body_size
UPLOAD_MAX_SIZE_MB
云 WAF/CDN 上传限制
```

修改 `frontend/nginx.conf` 后必须重建 frontend 镜像。

### 15.6 Instagram 无法抓取视频

逐项检查：

```text
video_url 是否为 https://真实域名/videos-pub/{video_id}
外网是否无需登录即可 GET/HEAD
证书链是否正常
是否错误使用 localhost/内网 IP
视频是否已删除
是否被 CDN/WAF 的机器人策略拦截
是否支持 Range 请求并返回正确 Content-Type
```

先从服务器外部网络执行 `curl -I`，不要只在服务器本机测试。

### 15.7 重启后 Token 全部不可用

如果数据库中的加密凭证突然无法读取，检查 `SECRET_ENCRYPTION_KEY` 是否被更换。恢复原密钥后重启 API 和 Worker。不要通过重新填写所有 Token 来掩盖密钥管理问题。
