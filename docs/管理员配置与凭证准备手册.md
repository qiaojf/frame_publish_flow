# FrameFlow 管理员配置与凭证准备手册

> 适用版本：本项目截至 2026-09-29 的代码。适合负责收集资料、填写后台配置和安排续期的管理员。第三方平台的申请页面、审核规则可能变化，以文末官方链接为准。

## 先看这张表：哪些现在能用

| 项目 | 当前状态 | 管理员现在该做什么 |
| --- | --- | --- |
| Mock Platform／默认 Mock 账号 | 可用；不会向第三方发布 | 用于练习完整操作 |
| Instagram | 已实现 Reel 发布 | 准备专业账号、Meta App、授权 Token；配置后用真实视频验证 |
| YouTube | 已实现视频上传及 Access Token 自动刷新 | 准备频道、Google Cloud OAuth 凭证和 Refresh Token；配置后验证 |
| X | 有平台模板，实际视频上传／发帖未实现 | 先收集资料；暂勿作为正式发布目标 |
| Facebook | 有平台模板，实际 Page 视频／Reel 发布未实现 | 先收集资料；暂勿作为正式发布目标 |
| Mock Video Model | 可用；生成测试视频 | 无需外部账号或密钥 |
| MiniMax Hailuo 2.3 | 已实现文生视频、图生视频 | 准备 MiniMax API Key；由技术人员安全写入模型账号，见下方注意事项 |
| Google Veo 3.1、Runway Gen-4.5、Runway Seedance 2.5、Luma Ray 3.2 | 有模型模板；默认停用且未配齐真实调用参数 | 先准备资料；不要只打开“启用”开关就交给用户使用 |

“可用”表示本项目有实际执行流程，不表示外部平台已经批准您的账号、权限、额度或公开发布资格。第三方账号的登录密码只用来登录其官网，**不要填入 FrameFlow 的 Client Secret、Token 或其他配置框**。

## 1. 管理员登录后，先认识三个位置

本机 Docker 当前页面是 `http://localhost:5174`。登录后展开左侧 **系统配置**：

1. **发布平台**：定义“发布到哪里”，例如 Instagram、YouTube。这里主要是平台名称、编码、适配器类型、API 地址和发布表单字段。
2. **发布账号**：定义“用哪个账号发布”。同一个平台可以有多个账号。这里填写用户名／频道 Handle、Access Token、Refresh Token、Client ID 等。
3. **视频模型**：定义“用哪个模型生成视频”。模型背后还连接着“模型服务商”和“模型账号”；当前网页没有单独的服务商／模型账号管理页，只有后端管理接口。

建议先用现成模板，**不要新建同名平台或随意修改“平台编码”“Adapter Type”“模型编码”**。这些字段是程序识别用的，并非对外展示名称。若页面未看到模板，先请部署人员确认后端初始化（Seed）已完成。

### 配置前统一准备

- 指定每个平台和模型服务的公司负责人，并让其保管官网登录方式及双重验证设备。
- 为真实发布准备一个短小、可公开的测试视频，确认有发布权、音乐及肖像授权。
- 为 Instagram 准备外网可访问的 **HTTPS** 视频地址。`localhost`、`127.0.0.1`、公司内网地址都不能被 Instagram 的服务器读取。本系统发布页会根据当前访问域名生成 `/videos-pub/{视频ID}`；正式测试必须通过公网 HTTPS 域名访问系统，并让该路径转发到后端。
- 使用公司密码管理器保存原始密钥及续期负责人；交接表只写密钥名称、所属账号和到期日，**不要写明文值**。

## 2. 发布平台页怎么填

进入 **系统配置 → 发布平台**，找到现成的 X、Instagram、YouTube、Facebook 或 Mock 模板，点 **配置**。页面字段含义如下：

| 页面字段 | 填写方法 |
| --- | --- |
| 平台名称 | 给人看的名称，保留现成的 `Instagram`、`YouTube` 等即可 |
| 平台编码 | 程序用值：`instagram`、`youtube`、`x`、`facebook`、`mock-platform`；不要改 |
| Adapter Type | 程序用值：分别是 `instagram_graph`、`youtube_data_api_v3`、`x_v2`、`facebook_graph`、`mock_publish`；不要改 |
| API Base URL | 保留模板默认值；Instagram 为 `https://graph.instagram.com`，YouTube 为 `https://www.googleapis.com/youtube/v3`，X 为 `https://api.x.com`，Facebook 为 `https://graph.facebook.com` |
| 状态 | 先保持停用；账号资料齐全并验证成功后再启用。Mock 可保持启用 |
| 发布能力（JSON） | 控制发布页显示哪些输入框。保留模板内容；不要在这里填 Token、密码或 App Secret |

当前网页**不显示**平台的 `api_version`、`auth_type`、`extra_config` 等高级字段。Instagram 模板内的 API 版本及 YouTube 的上传／刷新地址已经在初始化数据中；如官网要求变更这些值，请技术人员通过后端配置核对，管理员不要靠修改“发布能力 JSON”处理。

## 3. 发布账号页的通用填法

进入 **系统配置 → 发布账号 → 新增账号**，先选发布平台，再填写。编辑已有账号时，平台不能更改；需要换平台时新建账号。

| 页面字段 | 意思与用法 |
| --- | --- |
| 账号名称 | 管理员能认出的名字，例如 `公司官方 Instagram` |
| 账号标识 | 该账号的公开用户名／业务标识。它不是密码；Instagram 建议填真实用户名，YouTube 可填频道 Handle |
| YouTube 频道名称 | 仅 YouTube 显示。填频道 **Handle**，例如 `@Qiao-f7p`，也可粘贴对应的频道主页 URL；不要填普通显示名称 |
| Instagram User ID | 仅 Instagram 显示。填官方 API 返回的数字 ID，不是 `@用户名`，也不是 `MEDIA_CREATOR` |
| 客户端 ID、客户端 Secret | 第三方开发者 App 的 OAuth 凭证；按平台小节填写。不是平台账号登录密码 |
| 访问令牌（Access Token） | 由第三方授权流程产生，用来代表该账号调用 API |
| 刷新令牌（Refresh Token） | 只有授权流程实际发放时才填；不要把 Access Token 复制过来 |
| Token 过期时间 | 按官方授权结果或 Token 检查工具的真实到期时间填写；不要随意选一个未来日期 |
| OAuth 权限范围 | YouTube 会出现预设的 `youtube.upload`、`youtube.readonly`；须与实际授权得到的权限一致 |
| 其他配置（JSON） | 放非机密的附加信息，例如频道 Handle；不要把 Token 或密码写进 JSON |

编辑账号时，安全字段只显示脱敏提示。**留空表示沿用原值**，不是把原值清空。新 Token 要完整粘贴到对应输入框再保存；保存后只能看到脱敏值。当前网页没有“一键连接 OAuth”或“一键测试账号”按钮；真实授权 Token 需先在第三方平台取得，再填入本页。

### 3.1 Instagram：专业账号发布 Reel

**先准备**：公司 Meta 开发者 App、一个 Instagram Business 或 Creator 专业账号、该账号的真实用户名、`ig_user_id`、具有内容发布权限的 Instagram User Access Token、实际到期时间。当前项目使用 **Instagram API with Instagram Login**；这种方式不要求为该专业账号绑定 Facebook Page。授权至少需要 `instagram_business_basic` 与 `instagram_business_content_publish`。正式对外服务涉及 Meta 审核和访问级别，需由 App 负责人确认。[Meta 官方 Instagram API 说明](https://www.postman.com/meta/instagram/folder/1z5vxzu/instagram-api-with-instagram-login)

**取得资料**：App 负责人在 Meta 开发者后台为公司专业账号授权；用官方工具检查 Token 有效期及权限；用该 Token 查询账号资料，记录返回的 `id` 和 `username`。不要把“账号类型”（如 `MEDIA_CREATOR`）当用户名，也不要把 App ID 当 `ig_user_id`。若最初得到短效 Token，请由 App 负责人按 Meta 当前流程换取／续期长效 Token。[Meta 官方 Instagram API 集合](https://www.postman.com/meta/instagram/collection/6yqw8pt/instagram-api)

**本系统中填写**：

1. **发布平台**：使用现成 `Instagram` 模板；确认 API Base URL 是 `https://graph.instagram.com`，待账号验证后启用。
2. **发布账号**：平台选 `Instagram`；账号名称写公司可识别的名称；账号标识写真实 Instagram 用户名（不需要 `@`）；Instagram User ID 填数字 `id`；访问令牌填该专业账号的 Token；过期时间填官方显示值。
3. 若公司希望把 Meta App ID 和 App Secret 也登记到此账号，可分别填 **客户端 ID**、**客户端 Secret**；现有 Instagram 发布流程实际使用的是 `ig_user_id` 和 Access Token，填写 App 凭证不会自动完成授权或自动续期。**刷新令牌**留空，除非所用授权流程明确提供了这种令牌。
4. 保存后使用真实测试视频发布一次 Reel，在 **发布记录**里核对结果，并到 Instagram 账号主页确认视频出现。发布前确保视频的 `/videos-pub/...` 是公网 HTTPS、无需登录可取到视频文件。[Meta 官方 Reel 发布流程](https://www.postman.com/meta/instagram/documentation/23987686-9386f468-7714-490f-9bfc-9442db5c8f00)

**到期以后**：当前 Instagram Adapter **不自动刷新 Token**。到期前由 App 负责人按 Meta 官方流程更新／重新授权；管理员在 **发布账号 → 编辑**中替换访问令牌和真实过期时间，再发一条测试 Reel。若权限、专业账号状态或 App 审核状态变化，先在 Meta 后台处理，单改到期日期无效。

### 3.2 YouTube：频道上传视频

**先准备**：拥有目标 YouTube 频道的 Google 账号、频道 Handle（如 `@Qiao-f7p`）、Google Cloud 项目、已启用 YouTube Data API v3 的 OAuth Client ID 与 Client Secret，以及该频道授权后得到的 **Access Token 和 Refresh Token**。本项目要求授权范围同时包含 `https://www.googleapis.com/auth/youtube.upload` 和 `https://www.googleapis.com/auth/youtube.readonly`；授权时需取得离线访问权限，才能拿到 Refresh Token。Google Cloud 的 OAuth 同意页面、测试用户和审核状态要由项目负责人确认。[Google 官方 OAuth 指南](https://developers.google.com/youtube/v3/guides/auth/server-side-web-apps)

**本系统中填写**：

1. **发布平台**：使用现成 `YouTube` 模板，API Base URL 保持 `https://www.googleapis.com/youtube/v3`；授权和账号填写完成后启用。
2. **发布账号**：账号名称填内部名称；**YouTube 频道名称**填 `@频道Handle` 或频道主页 URL，例如 `https://www.youtube.com/@Qiao-f7p`；客户端 ID／Secret 填 Google OAuth 凭证；访问令牌／刷新令牌分别填 OAuth 返回值；Token 过期时间按返回值填写。
3. **OAuth 权限范围**页面会预填两项。核对真实授权确实包含这两项；手工勾选并不会替 Google 授权。账号标识可以填频道 Handle，但不能代替专门的“频道名称”字段。
4. 保存后用一个简短视频上传测试，在 **发布记录**中点击“查看发布内容”“打开平台主页”，确认分别进入正确的视频和频道。若 Google 项目尚未通过相应审核，API 上传的视频可能被限制为私密；这不是“隐私状态”字段失效。[YouTube 官方上传说明](https://developers.google.com/youtube/v3/docs/videos/insert)

**到期以后**：本项目 YouTube Adapter 在 Access Token 将过期、已过期或收到 401 时，会使用已保存的 Client ID、Client Secret、Refresh Token 自动获取新 Access Token，并更新数据库。如果报“重新授权”“Refresh Token 无效”或权限不足，请 Google 项目负责人重新授权目标频道，管理员再编辑账号替换新 Refresh Token、Access Token 和到期时间；不要仅延长日期。授权前应核对登录的确是目标频道。[Google 官方刷新说明](https://developers.google.com/youtube/v3/guides/auth/server-side-web-apps#offline)

### 3.3 X：目前只能预备资料

**准备**：公司 X 账号、X Developer App、账号用户名、OAuth Client ID；若选择保密型客户端，还需要 Client Secret；以及按官方授权得到的用户 Access Token、Refresh Token 和有效期。视频发帖通常需要 `tweet.write`、`media.write`，需要持续授权时还需 `offline.access`。费用、额度和 App 权限以 X Developer Console 为准。[X 官方 OAuth 权限](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code)、[视频上传接口](https://docs.x.com/x-api/media/upload-media)

**本系统现状**：`X` 模板的 `x_v2` Adapter 只检查配置并整理请求参数，没有实际完成视频上传和发帖。管理员可以保管上述资料，平台与账号维持停用。即使把 Token 填进发布账号并启用，也不会成功发布到 X；须先由开发人员完成真实发布及刷新流程。

### 3.4 Facebook：目前只能预备资料

**准备**：公司管理的 Facebook Page、具有相应 Page 任务权限的人员、Meta App、Page ID，以及通过授权得到的 **Page Access Token**。如果计划发布 Page Reel，还应先确认该 Page 与 App 具备相应发布权限和审核资格。请区分 Page Access Token 与普通用户 Token。[Meta 官方 Page Token 流程](https://www.postman.com/meta/facebook/request/bqfxwbp/get-access-tokens-of-pages-you-manage)、[Meta 官方 Reels 流程](https://www.postman.com/meta/facebook/folder/simabyk/reels-publishing)

**本系统现状**：`Facebook` 模板的 `facebook_graph` Adapter 尚未实现真正的 Page 视频／Reel 上传。当前发布账号网页也没有独立的 Page ID 输入框；即使把 Page Token 填入，也不能据此完成发布。请先保持停用，待开发人员完成适配后再按实际字段配置。Page Token 失效时，应由 Page／App 负责人重新取得有效 Token。

### 3.5 Mock：管理员练习

使用现成 `Mock Platform` 和 `默认 Mock 账号`。无需第三方账号、密码、Token 或公网域名。通过 **制作视频 → 我的视频 → 发布视频 → 发布记录** 走一遍流程，熟悉按钮和状态；Mock 的“发布成功”只表示内部模拟成功，不会出现在 Instagram、YouTube 等网站。

## 4. 视频模型分别需要准备什么

进入 **系统配置 → 视频模型 → 配置** 时，先确认打开的是要修改的那一行。当前页面各字段含义如下；真实模型请先阅读对应小节的界面限制，再决定是否保存。

| 页面字段 | 含义与建议 |
| --- | --- |
| 模型名称 | 页面显示名，例如 `MiniMax Hailuo 2.3` |
| 模型编码 | 系统内部唯一标识；保留已有值 |
| 服务商 | 例如 `MiniMax`、`Runway Developer API`；不能用它代替真正的服务商账号配置 |
| Adapter Type | 程序调用方式；保留模板值，不要把模型名称填进这里 |
| Model ID | 第三方接口识别的模型名；以当前已实现的 Adapter 和官方账号权限为准 |
| API Base URL | 服务地址；不要填官网登录页的网址 |
| API Key | 供应商签发的接口密钥，不是登录密码；真实模型的填写限制见各小节 |
| 超时时间 | 模型配置的超时值，通常保留模板默认值；MiniMax 还受服务器运行参数控制 |
| 文生视频／图生视频 | 控制普通用户能选的生成方式，只勾选已验证可用的方式 |
| 时长／宽高比／分辨率 | 控制普通用户的可选项；必须与模型真实能力一致 |
| 最大参考图数／图片大小 | 上传限制；不能超过第三方及服务器允许的上限 |
| 其他配置（JSON） | 程序参数，不是密码箱；不要在这里粘贴 API Key |
| 状态 | 真实模型完成凭证和生成测试后再启用 |

### 4.1 Mock Video Model

无需注册模型服务、充值或填写 API Key。保持现成模板启用即可。它借助服务器上的 FFmpeg 生成测试视频，适合验证“生成 → 视频库 → Mock 发布”的操作链。

### 4.2 MiniMax Hailuo 2.3

**准备**：公司 MiniMax API 平台账号、可以使用视频生成 API 的权限与余额、由平台签发的 **API Key**。这不是 MiniMax 网页登录密码。当前模板名称是 `MiniMax Hailuo 2.3`，模型 ID 是 `MiniMax-Hailuo-2.3`，Adapter Type 是 `minimax_hailuo23`，服务地址默认 `https://api.minimax.io`。[MiniMax 官方入门](https://platform.minimax.io/docs/guides/quickstart-preparation)

**重要的当前界面限制**：后端将密钥存在独立的“MiniMax 模型账号”中；网页的 **视频模型 → 配置**虽有 API Key 输入框，保存时会重写模型能力信息，可能丢失 Hailuo 模板中的分辨率／时长组合等高级限制。因此，**不要为了更新 Hailuo Key 而直接保存整个视频模型表单**。管理员负责取得 Key 并安全交给有权限的技术人员，由其通过后端的 **模型账号管理接口**更新现成 `MiniMax PoC Account` 的 `api_key`，保留模型原有能力配置，再做一次真实生成测试。该接口的“配置测试”只检查字段完整性，不能证明第三方 API 已实际成功调用。

**过期、轮换或余额不足**：由 MiniMax 账号负责人在官方平台检查 Key 状态和余额；需要轮换时生成新 Key，按上述方式更新模型账号并做一次短视频测试。MiniMax API Key 在本系统里没有“自动刷新”机制。现有模板支持 6／10 秒，768P；1080P 仅与 6 秒组合。官网产品更新不代表本系统自动切换到新模型；不要擅自改模型 ID。[本项目 Hailuo 需求和参数](MiniMax_Hailuo2.3接入开发需求_Codex.md)、[MiniMax 视频文档](https://platform.minimax.io/docs/guides/video-generation)

### 4.3 Google Veo 3.1、Runway Gen-4.5、Runway Seedance 2.5、Luma Ray 3.2

这些是系统预置的**停用模板**，便于后续接入；不能仅凭界面填一个 API Key 就认定可用。

| 模板 | 管理员预先向供应商／公司负责人收集 | 当前还需要技术人员完成 |
| --- | --- | --- |
| Google Veo 3.1 | Google Cloud 项目、Vertex AI 可用权限、项目 ID、Region、服务账号或工作负载身份方案、预算 | 配置 Google 认证与真实请求参数，验证生成和下载 |
| Runway Gen-4.5 | Runway 开发者账号、API Key、可用模型与额度 | 配置真实接口路径／结果字段、验证生成和下载 |
| Runway Seedance 2.5 | 同上；另确认该模型对账号开放 | 同上，并核对多素材能力 |
| Luma Ray 3.2 | Luma 开发者账号、API Key、模型可用权限与额度 | 配置真实接口路径／结果字段、验证生成和下载 |

这四个模板使用可配置的通用 Adapter，但初始化数据没有提供完整的 `operation_paths` 等实际请求配置；当前后台网页也没有模型服务商、模型账号的独立编辑页。请保持停用。由技术人员完成接口适配并实测成功后，再让管理员启用给普通用户选择。

## 5. Token、API Key 和 `.env`：放在哪里

**日常第三方凭证放管理后台的加密字段，不放项目根目录 `.env`。** 发布账号的 Client Secret、Access Token、Refresh Token，以及模型账号的 API Key 会由后端加密后存入数据库，页面只显示脱敏值。现有根目录 `.env.example` **没有** `INSTAGRAM_ACCESS_TOKEN`、`YOUTUBE_REFRESH_TOKEN` 或 `MINIMAX_API_KEY` 的读取配置；自行添加同名环境变量不会自动更新后台账号。

根目录 `.env` 主要由部署人员维护。下表是与管理员工作相关的项目变量：

| 变量 | 用途 | 管理员应知道 |
| --- | --- | --- |
| `SECRET_ENCRYPTION_KEY` | 加密数据库中的第三方 Secret | 必须安全备份；随意改动会使已保存凭证无法解密 |
| `JWT_SECRET_KEY` | 系统登录令牌签名 | 部署时更换示例值；不等于第三方 Token |
| `DEFAULT_ADMIN_USERNAME`、`DEFAULT_ADMIN_PASSWORD` | 首次初始化管理员账号 | 不是 Instagram／YouTube 的密码；已有账号不会因改 `.env` 自动改密码 |
| `PUBLIC_BASE_URL` | 后端公共地址配置 | 当前发布页的 `/videos-pub/...` 实际由浏览器访问域名生成；只改此变量不能让本机地址成为公网 URL |
| `CORS_ORIGINS` | 允许哪些网页域名访问后端 | 换域名时由部署人员核对 |
| `MINIMAX_API_BASE_URL` | MiniMax 初始化默认地址 | 已保存到数据库的服务商地址不一定随它改变；变更时需技术人员核对现有记录 |
| `MINIMAX_POLL_INTERVAL_SECONDS`、`MINIMAX_GENERATION_TIMEOUT_SECONDS`、`MINIMAX_HTTP_TIMEOUT_SECONDS` | MiniMax 任务等待与请求超时 | 属于服务器运行参数，通常无需改 |

如果部署人员需要调整这些变量：在项目根目录编辑 `.env`，每行采用 `变量名=值`；保存后重新创建 `api` 和 `worker` 容器使环境生效。示例命令如下，**不要把真实密码或 Token 写进此手册或聊天记录**：

```powershell
docker compose up -d --no-deps --force-recreate api worker
```

若是直接在电脑上运行后端，而不是 Docker，后端进程使用 `backend/.env`，修改后需要重启 API 和 Celery Worker。域名及 HTTPS 转发还需按[服务器部署与域名切换指南](服务器部署与域名切换指南.md)检查。普通管理员无需自己编辑 `.env`；可把要调整的变量名和期望效果交给部署人员。

## 6. 到期、异常和交接时的操作清单

| 现象 | 先做什么 | 下一步 |
| --- | --- | --- |
| Instagram 发布提示 Token 过期／权限不足 | 找 Meta App 负责人确认专业账号、权限和 Token 有效期 | 取得新 Token，编辑发布账号的访问令牌及过期时间，再测试 Reel |
| Instagram 提示视频 URL 不可访问 | 在手机移动网络或外部浏览器打开 `/videos-pub/...` | 请部署人员修复公网 HTTPS、域名和反向代理，再重试 |
| YouTube 提示 `refresh_token`、`invalid_grant` 或重新授权 | 核对 Google 项目、授权频道和 Refresh Token | 重新完成 OAuth 授权，编辑账号凭证并做短视频上传测试 |
| YouTube 视频只能私密观看 | 核对上传请求的隐私设置及 Google 项目审核状态 | 由 Google Cloud 项目负责人处理审核／限制 |
| MiniMax 提示 Key 无效或余额不足 | 到 MiniMax 控制台核对 Key、权限及余额 | 更新模型账号 Key 或充值后，做一次真实短视频生成 |
| X／Facebook 发布失败 | 确认是否误把模板启用 | 先停用，等待实际发布流程开发完成 |

每次 Token 或 API Key 更新后，记录“负责人、更新日期、下次检查日期”，并做一次小范围真实测试。不要通过修改数据库、篡改到期日或反复重试来掩盖失效。离职交接时先移交第三方平台的管理员权限和双重验证方式，再检查本系统使用的 App、频道、页面与密钥是否仍由公司控制。
